# Front v9 — штаб и серверная карта

Это обновление для установленного Front v8 с мелкими зонами. Сделай резервную копию мира и заменяемых файлов. Архив не содержит конфиг координат: твои зоны, очаги и базы остаются прежними. Ошибка `migrated` исправлена.

## Minecraft

Полностью закрой игру. Скопируй содержимое `minecraft` в папку Minecraft экземпляра с заменой. Запусти заново: обновились серверные скрипты и клиентский GUI. Карту высот и регистрацию кафедры из предыдущего обновления оставь установленными.

В `/front hq` нажми **HQ+**. Здесь находятся почта, РП-профиль и спецоперации. Интерфейс переключается вместе с языком штаба: RU / UK / EN.

## Что изменилось

- Стратегическая экспансия и движение, назначаемое директором, работают только в активных зонах рядом с игроками Overworld. Радиус берётся из `activeRadiusSectors`. Вне их контроль заморожен, удалённого истощения изоляцией больше нет. Другие моды продолжают выполнять свой ИИ в загруженных чанках — это не глобальная остановка сервера.
- Уже существующий общий скан сущностей раз в 20 секунд дополнительно сохраняет сведения об обороне. Второго полного обхода мира нет. Сведения заменяются только после полного загруженного обследования активной зоны. Выгруженные зоны не выдаются за пустые.
- Учёт обороны: солдаты из `alliedEntities` и явно отмеченная союзная техника Superb Warfare. Техника считается условно за четыре бойца; пять единиц силы — достаточная оборона. Порог можно задать `rememberedDefenceMinimum`. Это информационная оценка, не виртуальная армия: любой неактивный сектор заморожен независимо от числа солдат. При возвращении игрока работают реальные юниты, а не запомнённый бонус.
- Для союзной SBW-техники назначь тег `front_friendly_vehicle` точной выбранной сущности. Не назначай тег всему моду: иначе посчитается и противник. Владение/экипаж автоматически не определяются.
- Юниты не копируются и не восстанавливаются из счётчика. Их хранит Minecraft. Роботы директора уже создаются с `PersistenceRequired`; новая система не удаляет миномёты или ПВО из-за отсутствия игрока. Мирная сложность, смерть и очистители сущностей всё ещё могут их удалить.
- Реки: максимум 5% вероятности попытки продвижения на цикл в речную зону; дополнительно сохраняется сильный штраф к приросту контроля. Наземные роботы в воде речного биома получают краткое замедление III. Мосты не блокируются вручную: на суше эффекта нет. Нового алгоритма поиска переправ нет, нативный ИИ остаётся модовым.
- Почта: последние восемь записей видны в GUI, хранится до ста. Одинаковые события в одной зоне за минуту объединяются. Отмечать прочитанным можно отдельно каждому игроку. Чат не получает спам об освобождении зон. Полный сброс фронта очищает почту, задачи и учёт обороны.
- РП-профиль: свободная должность, позывной и текстовая эмблема. Должность **не даёт** прав администратора и не меняет роль авторизации CC. Редактор рисованных портретов и графических флагов пока не реализован.

## Спецоперации

Вкладка предлагает три вида задачи на существующего робота в загруженной зоне БД, в пределах 512 блоков:

- Миномётчик — уничтожить назначенного `crusty_chunks:mortarer`. Новая миномётная поддержка в этой зоне подавляется на 10 минут; уже живые миномётчики остаются.
- Снабженец — уничтожить назначенного `crusty_chunks:worker`. Стратегическое продвижение в зоне приостанавливается на 10 минут. Это условное задание на снабжение, не генерация склада.
- Командир — уничтожить назначенного `crusty_chunks:commander`. Стратегическое продвижение в зоне приостанавливается на 10 минут.

Координаты при принятии — последняя известная позиция цели, не постоянный радар. Цель может перемещаться. Один игрок — одна задача, срок 30 минут. Засчитывается убийство именно назначенной цели этим игроком внутри зоны БД. Если её убивает другой участник, задача снимается без награды. После успеха действует десятиминутный перерыв. Задания не создают дополнительных мобов и не грузят чанки. Нет целей вне зоны БД, виртуального командования и автоматического строительства укреплений.

Это базовые операции; отдельные уровни сложности, задания на ПВО и настоящие объекты-склады не реализованы. ID ПВО нельзя надёжно угадать: потребуется определить установленные юниты.

## Сервер карты CC

Используй **отдельный серверный компьютер CC**, чтобы программа не мешала циклу существующего сервера Military-system. На нём должны находиться существующие `server/modules/auth.lua`, `server/modules/storage.lua` и актуальная база пользователей `data/users`. Если база скопирована, новые регистрации нужно переносить отдельно; автоматической синхронизации базы нет.

1. Скопируй `computer/server/front_map_host.lua` в `/server/front_map_host.lua` этого компьютера.
2. Поставь рядом кафедру с периферией `front_map` из прошлого обновления.
3. Подключи проводной модем и сетевой кабель к клиентским компьютерам. Беспроводной режим намеренно запрещён: этот новый канал не использует шифрование старого радара.
4. Создай `/data/front_map/groups.json` по образцу `groups.example.json`. Ключ — ID аккаунта из базы Military-system; значение — внутренний ASCII-ID государства. Одинаковое значение означает общие точки. Без назначения группы вход запрещён.
5. Запусти `server/front_map_host.lua` и запомни ID компьютера. Держи программу запущенной.
6. На клиенте замени `/pr/military_map.lua` файлом из архива. Запусти `pr/military_map.lua` либо `pr/military_map.lua monitor`.
7. При первом запуске введи ID сервера; затем ID пользователя Military-system и пароль. Пароль на клиенте не сохраняется. Сессия действует 30 минут; после истечения перезапусти приложение и войди снова. Для смены сервера удали клиентский `front_map_connection.json`.

Карта читается и сохраняется на сервере: `/data/front_map/snapshot.json`. Общие точки — `/data/front_map/points.json`, отдельно для групп государств. Клиент хранит только ID сервера и текущие сведения в оперативной памяти. Старые локальные точки автоматически не импортируются; старые файлы не удаляются.

Солдат может смотреть; командир и генерал из существующей базы авторизации могут добавлять/удалять общие метки. РП-должность в Minecraft этих прав не даёт. Названия мест и описания вводят игроки как подписи точек. Разделение групп касается точек; общий фронт сборки остаётся одним.

Если кафедра недоступна, сервер может выдать последний сохранённый снимок с пометкой STALE. Последний снимок записывается при запросе карты; сам сервер CC не удерживает чанки загруженными. Время обновления Minecraft — игровое, 20 секунд при нормальном TPS.

Проводная сеть не заменяет криптографическую защиту: этот канал использует идентификаторы компьютеров и сессии. Не допускай чужие устройства к кабелю и серверу. Для публичного беспроводного доступа потребуется отдельно подключить проверенный зашифрованный транспорт Military-system.

## Проверка после установки

1. Убедись, что директор загрузился без ошибок. Открой штаб и HQ+.
2. Сохрани должность/позывной; проверь их после перезахода.
3. Поставь союзных солдат в полностью загруженную зону, подожди 20 секунд и обнови почту — снизу появится последний учёт.
4. Уйди из участка войны. Без игроков контроль не должен расширяться; после возвращения реальные бои возобновятся.
5. Возьми операцию рядом с соответствующим роботом, убей назначенную цель и проверь запись почты.
6. Подключи два CC-клиента с аккаунтами одной группы. Метка, поставленная командиром, должна появиться у второго после обновления. Аккаунт другой группы не должен видеть её.

Проверены синтаксис JS/Lua и имитационные тесты почты, учёта техники, задач/срока эффекта и экспансии без игроков. Запуск в Minecraft, GuiJS и обмен двух CC-компьютеров здесь не проверены. Это интеграционная версия, сначала проверь на копии мира.
